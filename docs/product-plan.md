# NTP Audit — แผนงานและระบบหน้าจอ

## ขอบเขต

ระบบภายในสำหรับนำเข้า Excel เงินเดือนรายเดือน ตรวจสอบก่อนบันทึก และคำนวณรายงานจากฐานข้อมูล โดยรายงานรายปีต้องแสดงรายการรายได้ รายการหัก วันลา และประวัติปรับเงินเดือนครบเทียบกับ Excel เดิม

ไฟล์ตัวอย่างใช้เพื่อศึกษารูปแบบเท่านั้น ไม่คัดลอกข้อมูลส่วนบุคคลลง repository หรือข้อมูลจำลอง

## สิ่งที่พบจากตัวอย่าง

- ไฟล์รายเดือนมีหลายชีต รวมทั้งชีตคำนวณและใบแจ้งเงินเดือน ชีต `คิดค่าจ้าง ` ระบุงวดกันยายน 2569 แต่ชีต `ปรับปรุง` และ `ไม่รวมปีใหม่` ระบุธันวาคม จึงห้ามอนุมานงวดจากชื่อไฟล์หรือชีตแรก
- ชีต `คิดค่าจ้าง ` ใช้หัวตารางหลายแถว แยกรายได้ OT รายการหัก และยอดสุทธิ มีสูตรในแฟ้ม จึงต้องอ่านทั้งสูตรและค่า cached พร้อมคำนวณตรวจซ้ำ
- ไฟล์รายปีมีชีตรายบุคคล โดยหัวรายการและจำนวนคอลัมน์ต่างกัน เช่น ค่าโทรศัพท์หรือประเภทวันลา จึงต้องใช้รายการจ่ายแบบ dynamic และสร้างรายงานจากข้อมูลรายเดือน ไม่ใช้ไฟล์รายปีเป็นแหล่งข้อมูลหลัก
- ชื่อชีตบุคคลไม่ใช่รหัสพนักงาน ระบบต้องใช้รหัสภายในและจับคู่ด้วยข้อมูลที่ยืนยันได้

## โครงข้อมูล

`company → employees → payroll_periods → payroll_entries → payroll_items`

ตารางประกอบ: `payroll_item_types`, `leave_records`, `salary_adjustments`, `imports`, `import_errors`, `audit_logs` และที่เก็บไฟล์ต้นฉบับแบบ private

จำนวนเงินใช้ `NUMERIC(14,2)` ใน PostgreSQL; ฝั่งแอปใช้หน่วยสตางค์แบบ integer หรือ decimal library; การนำเข้าต้องเป็น transaction และเก็บ version เมื่อแทนที่งวดเดิม

## ระบบภาพ

สี: พื้นหลัง `#F5F8F6`, พื้นผิว `#FFFFFF`, ตัวอักษร `#20352D`, เขียวหลัก `#176D52`, เขียวอ่อน `#E8F4ED`, เส้นแบ่ง `#DCE6DF`, สีเตือน `#9B661B`, สีผิดพลาด `#B4473E`

ตัวพิมพ์: IBM Plex Sans Thai สำหรับงานภาษาไทยและตัวเลขบัญชี, ขนาดเนื้อหา 14–15px, หัวหน้า 22–26px; ตัวเลขชิดขวาและใช้ tabular numerals

เลย์เอาต์: เมนูซ้ายคงที่บน desktop, หัวหน้าที่มีชื่อและตัวเลือกปี, เนื้อหากว้างสำหรับตาราง, แถบสรุปแบบประหยัดพื้นที่ หน้ามือถือใช้เมนูยุบและตารางเลื่อนแนวนอน

```
┌ เมนู ───────────┬ ชื่อหน้า                     ปี / การกระทำ ┐
│ ภาพรวม          │ สถานะข้อมูล 12 เดือน                    │
│ ข้อมูลรายเดือน  │ สรุปยอด / ตารางบัญชี                     │
│ รายงานรายปี     │ ข้อผิดพลาดหรือรายการที่ต้องตรวจ          │
│ พนักงาน ...     │                                        │
└─────────────────┴────────────────────────────────────────┘
```

ลักษณะเฉพาะคือแถบความครบของงวด 12 เดือนและตารางที่แยก `ยังไม่มีข้อมูล` ออกจาก `0.00` ชัดเจน ใช้เส้นและพื้นเขียวเฉพาะข้อมูลที่ยืนยันแล้ว ไม่ใช้ gradient หรือการ์ดตกแต่ง

## เส้นทางหน้าจอ

1. `/login` เข้าสู่ระบบ
2. `/` ภาพรวม
3. `/monthly` รายการงวด
4. `/monthly/2569/09` รายละเอียดงวด
5. `/import` อัปโหลด
6. `/import/preview` ตรวจพบข้อมูล
7. `/import/mapping` จับคู่คอลัมน์และพนักงาน
8. `/import/validation` ตรวจสอบความถูกต้อง
9. `/import/complete` ผลนำเข้า
10. `/reports/employee` รายงานรายปีรายคน
11. `/reports/company` รายงานรายปีบริษัท
12. `/employees` รายชื่อพนักงาน
13. `/employees/EMP001` โปรไฟล์พนักงาน
14. `/leave` วันลา
15. `/salary` ปรับเงินเดือน
16. `/imports` ประวัตินำเข้า
17. `/settings` ตั้งค่าและ mapping

## Session

1. โครงโปรเจกต์ ระบบภาพและหน้าจอ 17 เส้นทางด้วยข้อมูลสมมติ ตรวจ build แล้ว commit/push
2. PostgreSQL, การยืนยันตัวตน, บทบาท, audit และ persistence ตรวจ migration แล้ว commit/push
3. Excel import pipeline: ตรวจชีต, header mapping, พนักงาน, validation, transaction/version ตรวจด้วยไฟล์ตัวอย่างในเครื่องโดยไม่ commit ไฟล์ แล้ว commit/push
4. รายงานรายเดือน/ปี, วันลา, ปรับเงินเดือน, export, PWA และการทดสอบ end-to-end แล้ว commit/push

## เกณฑ์ตรวจ

- การนำเข้างวดกันยายนเพิ่มความครบของปีและยอดรายปีโดยไม่อัปโหลดไฟล์ซ้ำตอนเปิดรายงาน
- งวดซ้ำต้องเปรียบเทียบ/แทนที่/ยกเลิก และเก็บประวัติเดิม
- เดือนที่ขาดแสดง `—` ไม่ใช่ศูนย์
- รายการใหม่ไม่ทำให้ import ล้ม แต่ต้องให้จับคู่และจดจำการจับคู่
- ข้อมูลบุคคลที่อ่อนไหวไม่ปรากฏในข้อมูลจำลองหรือ dashboard
